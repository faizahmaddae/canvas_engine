## 1. Verdict

The engine layer is in good shape — command purity, history integrity, selection pruning, autosave/journal recovery, export byte-fidelity and viewport clamping all held up under direct attack, and several classes of bug the repo previously fixed (base-photo targeting, canvas-panel resurrection in-editor, paint dock read-side, text default-style leak) are genuinely fixed. **No P1 survived verification.** The single dominant theme is *seam disagreement*: whenever two surfaces can express the same operation — canvas vs. layers drawer, mode strip vs. overflow sheet, panel vs. picker, session overlay vs. background gesture router — they implement independent rules, and the seam between them is where every high-impact finding lives. The three recurring shapes are (a) a control that is **present, inert and silent** (which contract §10.3 explicitly forbids and which the codebase has already fixed once, for base-photo Align), (b) a **mode or scope that is armed but unrendered**, and (c) **destructive-by-default fall-through** — the gesture or status the code doesn't explicitly handle lands on the most destructive branch available (mask cancel, draft delete, "Shared").

Secondary theme: several UX contracts (§1 surface classes, §3 gesture fencing, §4 exit levels) are enforced on the surfaces that were migrated and simply absent on the ones that weren't — the divergence is invisible to CI because the tests cover the migrated surfaces only.

### P2-1 · Mask-edit destroys the whole draft on a stray tap outside the region
**Severity:** P2 · **Classification:** definite-defect · *(found independently by the `exit` and `gestures` lenses — merged)*

**Repro**
1. Add an image layer → Effects → apply any effect (this ungates the Selective tile).
2. Image strip → «انتخابی» / Selective. Scrim + region + 8 handles + Cancel/Done strip appear; AppBar and dock are hidden.
3. Shape the region, drag feather, flip invert — a minute of tuning.
4. Tap **once** on the grey pasteboard (or any canvas area no layer covers). In a photo project, any tap on the locked base photo outside the region does it too, via the `_protectedBaseHitAt` re-tap branch.
5. Variant B: tap a *different* layer through the scrim → selection change seam → same cancel.

**Expected:** contract §5 row 1 gives pointer ownership *anywhere* to the session overlay while crop/mask is open; §4 maps tap-empty to E3 (clear selection), not "abandon draft". Crop — same class D — swallows the identical tap.
**Actual:** the scrim is `IgnorePointer`, both selection surfaces decline to claim, so the tap reaches the always-mounted background detector → `handleTap` → empty-hit → `dismissActiveEditing` → `maskEditController.cancel()`. `cancel()` restores `entryMask` with **zero commands**, so undo cannot recover it. No confirm, no toast.

**Evidence**
- `lib/features/editor/application/editor_lifecycle.dart:111-113` — comment says *"an off-canvas tap is an explicit 'I'm done'"*, code calls `cancel()`. The comment names the opposite of what the code does.
- `lib/features/editor/application/editor_lifecycle.dart:162` — same call inside `closeObjectSubPanels` (selection-change seam), reached from `editor_screen.dart:148-150`.
- `lib/features/editor/presentation/widgets/mask_edit_overlay.dart:92-105` — scrim wrapped in `IgnorePointer`.
- `lib/features/editor/presentation/widgets/editor_canvas.dart:185-187` — background `GestureDetector`, ungated on mask.
- `lib/features/editor/presentation/widgets/canvas/canvas_gesture_router.dart:547` (empty hit), `:533-537` (protected-base re-tap); the router's only mask read is `:421`, the select-and-move claim.
- `lib/features/editor/application/mask_edit_controller.dart:192-209` — `cancel()` emits no command.
- `lib/features/editor/crop/presentation/crop_mode_overlay.dart:61` — full-screen `Material`, why crop is immune.

**Verifier note:** empirically reproduced with a widget test against the real `EditorCanvas` (tap at 8,8 → `active=false, selection=null`). Two scope corrections: a tap *on the masked layer itself* is a no-op (`select(sameId)` early-returns, `selection_controller.dart:52-55`), so this looks intermittent in manual testing; the long-press variant depends on `EditorScreen`'s selection listener and was not confirmed in the canvas-only harness — what *was* confirmed is that long-press puts the editor into multi-select mode underneath a still-open mask session (see P2-10).

**Why it matters:** silent, unrecoverable loss of in-progress work, triggered by the single most common "get me out of this" reflex on a scrimmed modal surface. Two sessions of the same documented class follow opposite rules.

### P2-2 · "Discard" on the Home draft card deletes the only copy in one tap; deleting a *saved* project requires a confirm dialog
**Severity:** P2 · **Classification:** intentional-but-questionable *(verifier reclassified from definite-defect)* · *(found by `persistence` and `availability` — merged)*

**Repro**

**Evidence**
- `lib/features/home/presentation/home_screen.dart:56-59` — `clearDraft(); setState(() => _pendingDraftJson = null);`

- `lib/features/home/presentation/widgets/recent_projects_grid.dart:447-479` — the guarded sibling path.
- fa labels collide: `app_fa.arb:555` («حذف», Discard) vs `app_fa.arb:200` («حذف پروژه؟») — same verb for the guarded and unguarded action.

**Verifier note:** the app already owns a non-destructive retirement path — `home_actions.dart:187-212 preserveOrphanDraft` promotes a draft to a real Project before clearing the slot — and does not reuse it here. **Severity:** P2 · **Classification:** definite-defect · *(found by `persistence` and `availability` — merged)*

### P2-5 · Multi-select mode stays armed and completely invisible below 2 members; canvas taps keep toggling
**Severity:** P2 · **Classification:** definite-defect · *(found by `selection` and `gestures` — merged)*

**Repro — entry**
1. Long-press empty canvas. Only a haptic fires; the chip is structurally impossible (count 0).
2. Tap a text layer → it selects, dock shows the text strip — looks like normal single-select.
3. Double-tap it to edit → the editor never opens (the multi branch returns before the double-tap check) and the selection flickers off/on.
4. Tap two overlapping layers repeatedly → tap-cycling is dead.

**Repro — falling back into it**
1. Long-press A, tap B → chip «چندانتخاب · ۲».
2. Tap B again → count 1 → **chip disappears**, dock swaps to A's single-layer strip.
3. Tap C → C is *added*, not selected. Tap the selected layer → it deselects.
4. Do the same de-toggle in the Layers drawer instead and the mode correctly ends.

**Expected:** whenever `selectionModeProvider == multi` — the flag that actually rewrites tap semantics — the chip renders, or the mode ends. The chip's own comment: *"so toggling-on-tap behaviour is never invisible."*
**Actual:** the chip gates on the **dock's derivation**, which requires `_actionableCount > 1`. Two providers, two different truths.

**Evidence**
- `canvas_chrome.dart:692-694` — `if (ref.watch(editorToolModeProvider) != EditorToolMode.multi) return SizedBox.shrink();`; `:150-155` the contradicted comment.
- `editor_mode_controller.dart:85-89` — `multi` only when `_actionableCount > 1`.
- `canvas_gesture_router.dart:486-507` — multi branch: `_resetTapCycle(); _disarmDoubleTapWindow(); selectionCtl.toggle(...); return;` — returns before the double-tap check at `:562-579`; also disables select-and-move at `:415`.
- `canvas_gesture_router.dart:664-685` — `handleLongPress`: `enterMulti()` then `add`/`clear`.
- `selection_controller.dart:69-71` — `toggle` has no membership rule.
- `layers_panel.dart:281-288` — the drawer *does* apply `if (selectedIds.length < 2) exitMulti();`, calling it an "Existing rule".
- Only editor-level `<2` guard, `editor_screen.dart:127-136`, is gated on `if (!pruned) return;` — it fires on commit-tick pruning, never on a user toggle.

**Verifier corrections:** escape is a single tap on empty canvas (undiscoverable but real); at count 1 the quick capsule still renders (`canvas_chrome.dart:137-145`, no mode gate), so a visible alternative text-edit path survives the dead double-tap.

**Why it matters:** a hidden mode rewrites the meaning of every tap, and the next destructive action reachable from the multi strip (batch Delete / batch Lock) then acts on a layer the user never meant to include.

### P2-8 · Colour undo granularity is wall-clock-based in exactly two surfaces
**Severity:** P2 · **Classification:** definite-defect · *(two `undo`-lens findings, one root cause: these are the only two hosts that still route colour through `live: true` committed commands instead of the `LiveOverlay` channel)*

**Repro A — discrete taps collapse**
1. Dock → Canvas → Background (Color). Tap three preset swatches in quick succession (<1 s apart).
2. Undo once → all three are undone. Space the same three taps >1 s apart and you get three entries.
3. Same with a rectangle: Shape → Style → three fill swatches quickly → one Undo.

**Repro B — one drag splits, two drags merge**
1. Rectangle → Shape → Style → custom-colour pill → wheel sheet.
2. Drag SV pad, release; within 1 s drag the hue bar, release. Undo once → **both** drags gone.
3. Now drag hue, hold still ~2 s mid-drag, keep dragging, release. Undo once → the fill lands on the colour it happened to be at when the pause elapsed — a value the user never chose.
4. Contrast Shape → Border → Colour, image Border/Shadow/Vignette, text colour: one entry per gesture, pauses irrelevant.

**Expected:** contract §3 — *"Two discrete taps are TWO entries, regardless of how close in time"*; §2 — the canvas background is *"the only sanctioned per-tick committed write"*, and even that exemption is for gesture-fenced streams. `SetCanvasBackgroundCommand`'s own docstring: *"Tapping a swatch should leave [live] at its default `false` so each tap is its own undoable click."* Roadmap 2.3 explicitly listed "shape fill/stroke/radius" for the overlay migration.
**Actual:** `_emit(committed: true)` fires `onChanged` **then** `onCommitted`; both hosts wire `onChanged` to a `live: true` command. The trailing `live: false` settle is value-identical, so `HistoryStack.execute` early-returns — it neither seals the entry nor refreshes `touchedAt`, leaving the top entry flagged live to absorb the next tap inside `kLiveMergeWindow`.

**Evidence**
- `color_picker_body.dart:234-236, 241-245` (`_pickSwatch` → `_emit(committed: true)`); `:413` the preset grid is the *default* level, so this is the shipped dock path; `:1603-1641` `_ImmediatePanArea` streams `onChanged` per pointer move.
- `canvas_panel_body.dart:170-171` and `shape_style_body.dart:144-145, 151-153` — the only two `live: true` colour hosts in `lib/features/editor`.
- `shape_style_body.dart:80-97` `_commitFill(live:)`; `:53-70` `_previewSlider`/`_commitSlider` — the contract-conformant channel, used by fill-opacity `:164-167` and radius `:190-193` **in the same class**. The Gradient angle slider (`fill_mode_section.dart:190-193`) is per-tick too, so the divergence is visible between two adjacent sliders in one panel.
- `history_stack.dart:89` (identity early-return), `:100-119` (merge gate); `engine_constants.dart:173` `kLiveMergeWindow = 1s`.
- `canvas_commands.dart:17-20, 56-61`; `shape_commands.dart:102-114` — `mergeWith` keys only on live + layerId + field-set; it cannot tell one gesture from the next.
- Correct siblings: `layer_border_body.dart:278-290`, `image_look_body.dart:280-286`, `text_bodies.dart:100-108`, `paint_tool_controller.dart:281-305`.

**Why it matters:** how much one Undo throws away depends on how fast the user tapped — invisible, unlearnable state — and shapes behave differently from every other object for the identical interaction.

## 3. Areas checked, no issue found

**Engine & history.** Stale-id integrity across undo/redo (`pruneMissing` runs on every commit tick *before* the selection seam). Draft sessions honour "Done = one entry, Cancel = zero, no-op = nothing" — crop has three short-circuits before building any command, mask commits only when `draft != entryMask`. Gesture fencing on the pointer channels is structural: `InteractionController.end()` epsilon-compares against the *document* transform, group drags composite into one entry, an eraser sweep is one command. `CompositeCommand.apply` returns the identical document when every child no-ops, so there are no net-zero composites. `redo()` backdates the re-pushed entry by one merge window. Bundling is correct where a naive implementation would produce two entries (text resize-mode + re-measure, border colour + width auto-promotion, base-photo delete + project-kind flip, all batch ops).

**Exit semantics.** Crop is airtight on every exit (full-screen `Material`, true no-op Cancel, back mapped to Cancel). The text composer honours §1-D's hard clause — `applyStyle`/`applyStylePreset` stage on the overlay during a live session, so Cancel really does revert mid-session styling, and both flags reset in `finally`. Font browser dismiss reverts and defuses its own debounce. Export preview blocks back while busy, disables close in lockstep, and keeps rendered bytes alive for in-place retry. Re-tap-active-tile = E1 is consistent across all five docks. No dialog commits on dismissal (notably layer rename, where a Cancel-pops-empty bug would wipe names). §6 session registry is derived, not stored.

**Persistence.** Back-out no longer loses unsaved work; every Home flow that starts a new session first promotes the pending draft. Preview bytes == file bytes (the size chip decodes the actual buffer). Thumbnails cannot go stale (`thumbnailVersion: 0` + `pngIsFresh` gate); thumbnail files are uuid-named and released only when unreferenced; corrupt project files are quarantined rather than emptying the library. The "Unsaved" badge is correct in every flow constructible. Cross-session journal contamination was investigated and is prevented by riverpod's listener teardown, not by luck. `pendingJsonForProject` resolves imported-image rebasing before comparing, so a container relocation doesn't produce a false resume offer.

**Gestures.** Handle-drag ownership claims the arena with zero slop and emits a defensive `end` on cancel/reject. Lazy-arena select-and-move genuinely doesn't steal sub-slop intents and abandons on a second finger (§5 row 6 holds). Paint's two-finger rescue asymmetry (discard draft, commit sweep) is correct per §7. Viewport guardrails: `_clampTranslation` is applied on every mutation path including `restore`, and `_effectiveMinScale` derives the floor from the fit for huge documents. OS-cancel recovery resets the gesture-start state. **RTL was checked specifically** — chrome that should mirror uses `PositionedDirectional`, and canvas geometry (`outsetSelectionQuad`, rotate-knob stem, `LayerSpaceMapper`) correctly takes no `TextDirection`; no gesture behaves differently under RTL.

**Availability & shell.** Eyedropper is hidden (not disabled) when unavailable. Layers-drawer reorder refusal explains itself with a snackbar. Overflow-sheet disabled rows (base-photo Align, reorder at stack ends) are correct. Emoji picker empty state guides. All three `pickImage` sites catch and route through `userMessageFor`. Journal write failure surfaces a 6-second snackbar naming cause and fix. Both Persian-digit size dialogs fold numerals before parsing. Tab/scroll/filter state survives navigation; the category-chip force-include prevents a filter applied with no selected chip. Project card metadata avoids the bidi-reversed-dimensions trap and the day-boundary "yesterday" case. Settings apply on the same frame, persist to both blob and mirrors, and disable Save at zero selections. No gesture-only affordances in the shell.

**Defaults.** `RecentColorsController` dedupes by full ARGB, chains persist writes, merges disk entries behind in-session picks. `ProjectViewportStore` legacy format loads as "re-fit". `paintStyleViewProvider` — the *read* half of the paint dock is correct. Sticker insertion doesn't inherit the text session style. `WordChipRow`'s untoleranced nearest-match is not reachable (its only call site passes a tolerance).

**Refuted (checked, not a defect):** "a corrupt template renders as 'No templates found'" — `assets/templates/**` is read-only in the bundle, and `migrated_template_assets_test.dart` decodes every manifest and document through the real parser, so a malformed template reddens CI before shipping. The loading-flash variant is unreachable because `NavShell` always launches on Home (which triggers the load) and the Templates tab can only mount later. The one residual — a sub-second "No templates found" flash when changing app *language* while the Templates tab is already mounted (the provider family is keyed on `languageCode`) — is at most a missing loading state, P3.
